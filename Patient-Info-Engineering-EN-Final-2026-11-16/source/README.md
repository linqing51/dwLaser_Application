# 方案 3 工程交接说明（2026-11-14）

本版按最新确认的要求改为设备内保存，USB 仅用于备份导出与整库导入。保留原参数主界面、开机患者图标高亮及“先退出治疗界面，再显示术后核对卡”的流程。

## 已确认的产品规则

- 设备最多保存 380 位患者，每位患者最多保存 10 条治疗记录。
- 姓名最多 18 个字符，本演示将空格计入长度；姓名必填，年龄和性别可选。字符集及编码由固件与串口屏字库统一定义。
- 容量满时阻止新增，可导出全部档案并清空设备，或手动删除旧资料。不自动覆盖最旧记录、不自动淘汰患者。
- USB 导出全部已保存资料，写入成功后清空当前设备患者和治疗档案，清除患者选择；失败保留设备原数据及 USB 原备份。编号计数不回退。USB 已有备份时，明确确认后替换该备份。
- USB 导入先校验版本、容量、字段与 ID，再明确确认替换设备全部患者及治疗记录。不做合并，不因同名或相同显示编号自动关联。
- 导入确认显示设备现有患者/记录数量、备份患者/记录数量，并提示先备份到另一块 USB。
- 单次导入不能只取前 380 人、前 10 条或截断长姓名；任一检查失败则整次拒绝，保留设备原档案。
- 治疗历史改为独立弹窗，每页固定 5 个记录位置。最多 10 条记录，两页显示；Previous / Next 按钮翻页，无滑动、无展开折叠。
- 患者列表采用按钮分页，每页 5 人；翻页与关闭操作合并到同一底栏，10 位患者只需两页。同名选择页通常 3 人，术后核对内每页 2 人。

## 正式设备与演示边界

正式设备应把已保存的患者资料、治疗记录及编号计数保存在设备非易失存储中。没有 USB 也可以登记、选择、编辑、删除患者以及保存治疗记录。

本 HTML 是交互演示，不是单片机固件。Device A/B/C 是三台各自独立的虚拟设备；USB A/B 是两个独立的虚拟备份介质。所有虚拟介质均只在当前网页运行内存中存在，不使用浏览器持久存储，不访问真实 USB，不上传数据。
Restart Demo Device 保留虚拟设备及 USB 已保存数据，清除运行状态与当前患者选择；刷新或关闭网页会重置整个演示。该演示重置不代表正式设备会丢失已保存数据。

存储写入成功才显示完成。真实设备的写入事务、断电保护、校验、寿命及故障恢复由固件实现；模拟测试不是物理存储可靠性验证。导入应先完整验证备份，再可靠提交替换，不能先擦除设备数据后才检查 USB。

## 术前、治疗与术后

1. 开机首次进入参数调节界面后，右上角患者图标高亮。医生开始调节功率、模式、脉冲时间或指示光时立即熄灭，包括触碰滑块但数值未变化、点击当前模式或达到参数边界的情况。点击患者图标进入患者列表也立即熄灭；直接进入 Ready 同样熄灭。返回参数界面不重复亮起，重启后重新提示一次。
2. 术前可以选择或登记患者，也可以不选患者开始治疗。主界面和治疗界面显示姓名与 ID，未选则显示 No patient selected。
3. 每次 Standby 结束本次手术。有实际输出时，先停止输出并回到不可操作的参数背景，再显示 Review Treatment Record。
4. 无实际输出时不创建治疗记录，保留当前患者选择。
5. 核对卡必须通过 Save Record 成功保存或确认 Discard Record 后退出。日期与时间在治疗结束时确定，不用保存时间替代。
6. 同名提示只负责选择身份，随后仍回核对卡完成保存。
7. 保存成功或确认放弃后，清除本次患者关联；不自动进入 Ready。
8. 当前患者达到10条记录上限时，Manage Records 直接打开该患者的治疗记录弹窗，不进入患者列表。USB Transfer 入口仅保留在患者列表页；治疗历史弹窗无 USB 入口。删除旧记录后点击 Back to Review 直接回核对卡继续保存。整个过程中患者身份和待核对快照保留。如果正在新建患者且设备已满380人，则没有该患者历史可查看，Manage Records 仍打开患者列表，供清理旧患者。
9. 待核对期间禁止导入、重启和切换设备，避免覆盖当前关联；允许导出已保存数据。导出明确不包含当前尚未保存的治疗。
10. 患者列表中的 Select Patient 与 Delete Patient 并排显示，删除患者无需进入历史弹窗。删除仍须确认，范围是患者资料及其全部已保存治疗记录，USB 备份不受影响。
11. 已选患者也可删除。删除成功后清除当前患者关联及相关表单资料；删除失败时保留原患者、历史及关联。删除其他患者不改变当前选择。
12. 如删除了本次未保存治疗关联的患者，保留待核对快照，自动回核对卡，要求重新选择或登记患者。不能沿用已删除身份自动保存或重建旧档案。删除旧治疗记录则仍保留患者与本次快照。

正式设备必须由固件确认已退出可发射状态后才显示核对卡。本演示的 450 ms 是视觉顺序，不能作为硬件安全判断。

## 存储及跨设备契约

- deviceArchives 保存每台虚拟设备各自的档案，volumes 保存每个虚拟 USB 的备份。USB 插拔不改变设备档案、患者选择或核对内容。
- 一个逻辑档案包含 archiveId、schemaVersion、patients、nextPatientNumber；本演示支持版本 1。设备间采用同一可兼容格式，不按来源设备序列号锁定。
- A 导出的备份可以导入 B/C，但必须通过显式导入和替换确认。单纯连接 USB 或切换设备不自动读取为本机档案。
- 导出是独立快照：之后设备上的编辑、删除和治疗保存不会自动更新 USB 备份，USB 也不会自动反向同步设备。
- 患者含内部 uid 和显示 ID（AR 0001 等）。显示编号按当前设备档案的新建患者顺序递增，与手术次数、列表排序、USB 插入次数无关。删除不回收编号，导入保留患者原有编号。
- 导入后的下一编号取本机已有计数与备份计数的较大值，避免恢复较旧备份后回退本机编号计数。不同独立档案仍可能有相同显示 ID；内部 uid 保持身份区分，本版不合并档案。
- 每条记录保留 uid、治疗结束时间、来源设备序列号、功率、模式、脉冲参数、波长、方案、输出时长和能量。跨设备导入后这些来源字段不重写；新治疗记录使用当前设备来源。
- 模拟的设备存储失败、USB 导出失败、USB 缺失和不兼容版本均有独立分支；失败不会显示成功或丢失原档案。
- JSON/UUID 是网页模型表达，不要求单片机直接复用 JavaScript 数据结构或算法。物理文件结构、设备固定字段布局、唯一标识生成及 USB 驱动由工程师按硬件落实。

## 串口屏实现建议

治疗历史弹窗复用同一固定模板：标题、5 行记录、5 个删除记录触摸区、Previous、Next、Edit Patient、Close。Delete Patient 仅位于患者列表，与 Select Patient 并排。翻页仅更新文字与所绑定的记录索引，不需要滑动动画或每页单独制作背景图片。
患者列表同理，复用 5 行模板。删除后重新计算页数；第二页已空时退回第一有效页。空历史显示提示，翻页按钮禁用。
历史按治疗结束时间从新到旧显示，每行同时显示治疗摘要、来源序列号及删除按钮。删除操作必须绑定真实记录索引/标识，不能只用当前页的第几行。

## 源码与验证

- app/page.tsx：患者、核对、固定历史弹窗、删除确认、分页和 USB Transfer 界面。
- app/globals.css：1024 × 600 固定布局、原设备 Myriad Pro 字体及黑灰背景。
- lib/demo-model.mjs：设备保存、容量校验、显式导入导出、治疗和身份状态。
- lib/i18n.mjs：中英文界面文字；以入口 HTML 的 lang="en" 或 lang="zh-CN" 选择语言，两版共用同一套交互和存储规则。姓名、ID及内部字段值不翻译。
- tests/：治疗闭环、存储独立性、容量边界、18/19 字符、原子失败、跨设备导入、编号、分页及删除后的待保存重试。

离线查看：解压后双击根目录 index.html，保留 assets 文件夹；无需联网或安装字体。
默认 Actual Size 按 1024 × 600 显示。画布外的演示控件不属于正式设备 UI；它们可通过网页滚动访问。设备内部患者界面采用固定布局与按钮翻页。

开发需 Node.js 22.13+；按 pnpm-lock.yaml 安装依赖。当前工作区复用 ../demo/node_modules。

- npm test：逻辑测试
- npm run typecheck：类型检查
- npm run build：生成 JS/CSS/字体内嵌的 dist/index.html
- node scripts/package-engineer.mjs：更新演示与工程压缩包

同时提供英文与中文离线入口；中文版工程包根目录 index.html 为中文版，english.html 为英文版。两版共用 assets，互相独立运行。源码构建默认输出英文版，打包脚本生成中文入口。本版不包含英文讲解稿。
英文界面沿用原设计 Myriad Pro，字体内嵌于 HTML。中文界面优先使用电脑自带微软雅黑，其次苹方、Noto Sans CJK SC；不下载在线字体。工程师需为正式串口屏配置中文设备字库。正文、数字及按钮额外字间距为 0；详情见 UI-SPEC.md。
浏览器自动访问仍受此前 file:// 策略限制；本次完成代码、布局尺寸、字体宽度、逻辑及构建检查，未声称完成浏览器逐页视觉验收。正式串口屏需按实际字库、亮度及触摸环境验收。

## USB B 预置演示及导出清空规则

USB B 预置 Emma Wilson 与 Daniel Chen 两位虚构患者，各有一条治疗记录。选择 USB B → 患者列表 → USB Transfer → Import from USB → 确认替换，设备原患者整库被这2位患者和2条记录替换。取消确认不改变设备。

导出须先可靠写入并校验 USB，再清空当前设备已保存档案；物理设备事务顺序由工程师落实。演示中的 USB 写入失败或设备存储失败均保留两侧原数据。如存在未保存治疗，摘要仍保留，原患者关联清除，需重新选择或登记患者后保存；导出不包含这份未保存摘要。
