## 编译验证要求（每次改动后执行）

本分支不进行 AC6 迁移，编译验证以 AC5 完整 Rebuild 0 Error 并生成 hex 为准：

1. `<uAC6>0</uAC6>` → AC5（armcc，`C:\Keil_v5\ARM\ARMCC`）Rebuild；
2. AC6（armclang，`C:\Keil_v5\ARM\ARMCLANG`，6.24）双编译器 0 Error 是 master 主线的要求，本分支不受该约束、不要求清零，待合并回 master 或将来专门的 AC6 迁移分支统一完成。

命令行：`UV4.exe -r targetBoard_G5_TRI_A1_20260915.uvprojx -o <日志> -j0`（UV4 路径 `C:\Keil_v5\UV4\UV4.exe`；`-r` 强制完整重编，`-b` 可能只做增量）。

验证结束后，工程文件应回到仓库规定的默认编译器设置，避免遗留无关改动。无硬件时仅能称为"编译级验证"，不得声称功能/时序已上板验证。

## 工具链已知坑（重要，避免重复踩坑）

- 若工程 ARM Compiler 选项为 **"Use default compiler version 5"（使用默认编译器版本5）**，在命令行 UV4 下可能因全局默认解析异常，把 AC5 工程错误解析到 `ARMCLANG` 目录、却仍调用 AC5 的可执行文件名，拼出不存在的 `C:\Keil_v5\ARM\ARMCLANG\Bin\ArmCC`，报 `CreateProcess failed`。
- 正确复位方式：Keil GUI → Options for Target (Alt+F7) → Target → ARM Compiler，**明确选择具体版本 `V5.06 update 7 (build 960)`**（不要用"默认"）。保存后工程会新增一行 `<pArmCC>5060960::V5.06 update 7 (build 960)::.\ARMCC</pArmCC>`，命令行即可正确解析到 `ARMCC\Bin`。
- 强制完整重编用 `-r`；`-b` 可能只做增量。

## 验证状态与判据

- **AC5（armcc）**：Code/RO/RW/ZI 等时点数字以最新 Keil 日志 Program Size 实测为准，不在此固化；判据为 0 Error 并正常生成 hex。警告仅允许来自第三方 ST USB 库 `usbh_cdc.c`（#225-D 格式化字符串）基线，非自编代码、非病历范围，不修改，自编代码保持零警告。
- **AC6（armclang）：本分支不迁移、不要求清零。** 已知阻断是 FreeRTOS 仍用 `portable/RVDS/ARM_CM4F` port（armclang 不识别 armcc 的 `__forceinline`），仓库内无 GCC/ARM_CM4F port；另有 dcHmiApp.c 的 static 声明冲突。本分支编译验证以 AC5 0 Error 出 hex 为准，详见根 AI_RULES.md 第 2 节。
