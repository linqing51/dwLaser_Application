## 工具链已知坑（重要，避免重复踩坑）

- **“Use default compiler version 5”在命令行 UV4 下可能解析异常**：把 AC5 工程错误解析到 `ARMCLANG` 目录、却仍调用 AC5 的可执行文件名，拼出不存在的 `C:\Keil_v5\ARM\ARMCLANG\Bin\ArmCC`，报 `CreateProcess failed`。
  - 正确复位：Keil GUI → Options for Target（Alt+F7）→ Target → ARM Compiler，**明确选择 `V5.06 update 7 (build 960)`**（不要用“默认”）；保存后新增 `<pArmCC>5060960::V5.06 update 7 (build 960)::.\ARMCC</pArmCC>`，命令行即可正确解析到 `ARMCC\Bin`。
- 命令行强制完整重编用 `-r`（`-b` 可能只做增量）：

```
& "C:\Keil_v5\UV4\UV4.exe" -r "targetBoard_G5_TRI_A1_20260915.uvprojx" -o "<日志>" -j0
```

## AC6 迁移的当前阻断点（专项启动时再核实）

- FreeRTOS 仍用 `portable/RVDS/ARM_CM4F` port（armclang 不识别 armcc 的 `__forceinline`），仓库内无 GCC/ARM_CM4F port；另有 `dcHmiApp.c` 的 static 声明冲突。
- 当前不迁移 AC6、不要求清零，编译验证以 AC5 0 Error 出 hex 为准；详见 `AI_RULES.md` 第 12 章。
